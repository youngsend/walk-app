# walk-app 開発フロー

最終更新: 2026-08-08

要件は [requirements.md](./requirements.md) を参照。

## 基本方針

**Expo Go で開発する。** iPhone に App Store から Expo Go を入れ、Mac で `npx expo start` して QR コードを読むと、実機でアプリが動く。ネイティブビルドは不要。

理由: この Mac は macOS 12 で Xcode 16.1 が入らず、ローカルビルドができない（[環境制約](./requirements.md#5-環境制約)）。Expo Go ならこの制約を回避でき、かつ**実際に外を歩きながら GPS を試せる**。

コードを保存すると数秒で iPhone の画面に反映される（Fast Refresh）ので、実機での試行錯誤が速い。

## 毎回の開発サイクル

```bash
npx expo start
```

1. Mac のターミナルに QR コードが出る
2. iPhone のカメラで読む（Mac と iPhone が**同じ Wi-Fi** にいること）
3. Expo Go が起動してアプリが表示される
4. エディタでコードを編集して保存 → iPhone に自動反映

同じ Wi-Fi に繋げない場合は `npx expo start --tunnel` を使う（遅いが確実）。

## ステップ

各ステップに「完了の定義」を置いた。ここを満たしたらコミットして次へ進む。

---

### Step 0: Expo Go で現状のアプリを表示する

**やること**

- iPhone に Expo Go をインストール
- `npx expo start` して現在の [app/index.tsx](../app/index.tsx) を実機に表示

**完了の定義**
iPhone に "Edit app/index.tsx to edit this screen." が表示される。
`index.tsx` の文字列を書き換えると iPhone の表示が変わる。

**なぜ最初にやるか**
ここが通らないと以降すべてが進まない。ネットワーク周りの問題を先に潰しておく。

---

### Step 1: 地図を表示する `F-1`

**やること**

- [app/index.tsx](../app/index.tsx) を `react-native-maps` の `<MapView />` に差し替える
- 初期表示位置は固定の座標（例: 自宅付近）でよい

**完了の定義**
iPhone に地図が全画面で表示され、指でズーム・移動できる。

**ポイント**
iOS では Apple Maps が使われるので API キーの設定は不要。Android を切り捨てている効用がここで効く。

---

### Step 2: 現在地を取得して地図に反映する `F-1`

**やること**

- `expo-location` で位置情報の許可を求める
- 現在地を取得し、地図の中心を現在地に合わせる
- 現在地マーカーを表示する

**完了の定義**
アプリ起動時に許可ダイアログが出て、許可すると自分のいる場所が地図の中心に来る。

**ポイント**

- 使う API は `requestForegroundPermissionsAsync()` と `getCurrentPositionAsync()`
- Expo Go では許可ダイアログの文言が Expo Go 自身のものになる。[app.json](../app.json) に書いた文言が反映されるのは開発ビルド以降なので、ここでは気にしない
- 許可を**拒否された場合**の表示も作っておく（拒否は普通に起きる）

---

### Step 3: 散歩を記録する `F-2`

このステップが本アプリの核。3 つに分けて進める。

#### 3-1. 位置の連続取得

`watchPositionAsync()` で位置を購読し、取得した座標を配列に貯める。
画面から離れる時に購読を解除する後始末を忘れないこと（バッテリーを食い続ける）。

**完了の定義:** 歩くと座標の配列が増えていくのが確認できる（画面に件数を出せば十分）。

#### 3-2. 軌跡の描画

貯めた座標を `<Polyline />` に渡して地図上に線を引く。

**完了の定義:** 実際に外を歩くと、歩いた道筋が地図に線で描かれる。

#### 3-3. 開始／停止と集計

- 「開始」「停止」ボタンで記録を制御する
- 停止時に総距離・所要時間・平均ペースを計算して表示する

距離は隣り合う座標間の距離を足し合わせて求める（球面距離の計算式が必要）。

**完了の定義:** 実際に散歩し、停止すると妥当な距離と時間が出る。

**ポイント**
GPS は止まっていても座標が微妙に揺れる。素直に足すと「動いていないのに距離が増える」ので、
一定距離以下の移動を無視するなどの処理がいずれ必要になる。まずは素直に実装して、実際に歩いて誤差を見てから対処する。

---

### Step 4: 記録を保存して履歴を見る `F-3`

**やること**

- 保存方式を決める（[未決事項](./requirements.md#6-未決事項)）
- 記録終了時に端末内へ保存する
- 履歴一覧画面を追加する（`app/history.tsx`）
- 一覧から選ぶと詳細画面でルートを表示する（`app/history/[id].tsx`）

**完了の定義**
アプリを完全に終了して再起動しても、過去の散歩が一覧に残っている。

**ポイント**
ここで初めて画面が複数になる。Expo Router のファイルベースルーティングを使う場面。
このあたりで `components/` や `lib/` にコードを切り出し始めるとよい。

---

### Step 5: ルートを提案する `F-4`

ここから難易度が上がる。地図表示ライブラリはルート探索をしてくれないため、外部 API の選定から始まる。

**やること**

1. ルーティング API を 1 つ選ぶ（候補は[要件定義の表](./requirements.md#f-4-散歩ルートの提案-p2)）
2. 実際に自宅周辺で試し、歩ける道を返すか検証する
3. 条件入力 UI と提案結果の地図表示を作る

**完了の定義**
「30 分で歩ける周回コース」を頼むと、実際に歩けるコースが地図に表示される。

**ポイント**
Step 4 までを一度自分で使い込んでから着手することを勧める。
実際に記録を取ってみると「本当に欲しい提案」の像が変わる可能性が高い。

---

## この先で判断が必要になること

- **バックグラウンド記録 `F-6`** — 「画面を消しても記録したい」と感じたら着手を検討する。
  開発ビルドが必要になり、macOS のアップグレードか年 $99 の出費が発生する（[環境制約](./requirements.md#5-環境制約)）。
  裏を返せば、それまでは追加費用ゼロで開発できる。

- **コードの整理タイミング** — Step 3 まではファイルを分けずに書いてよい。
  Step 4 で画面が増えた時点で `components/` `hooks/` `lib/` に切り出す。
  最初から整理しようとすると、何をどこに置くべきか分からないまま器だけ作ることになる。
