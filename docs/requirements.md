# walk-app 要件定義

最終更新: 2026-08-08

実現方法・調査データ・技術選定の根拠は [design.md](./design.md) を参照。
このドキュメントは「何を満たすべきか」だけを扱う。

## 1. 目的

**「大通りを避けた、毎回少しずつ違う散歩ルートを提案してくれる」個人用 iPhone アプリ。**

目的地までの経路は地図アプリでも出せるが、車向けの幹線道路を通りがちで、何度検索しても同じ道を出してくる。本アプリは「歩いて気持ちのいい道」かつ「前回と違う道」を提案することを中心に据える。

作者自身が日常的に使えることを最優先とし、App Store での一般公開は目的としない。

## 3. スコープ

### やること

- 目的地を指定すると、幹線道路を避けた徒歩ルートを提案する
- 提案するたびに、前回までと一部でも違うルートを出す
- 提案ルートを地図に表示し、自分の現在地を重ねる
- 散歩中は通信を発生させない
- 散歩の GPS 記録と履歴閲覧

### やらないこと

- App Store での配信・審査対応
- ユーザー登録／ログイン、他ユーザーとの共有
- Android 対応（コードは React Native なので将来可能だが動作確認しない）
- 音声によるターンバイターンのナビゲーション
- 周回コース（出発地に戻る）の生成 — [将来の検討事項](#6-将来の検討事項)

## 4. 機能要件

### F-8: 道路網データの取得 `P0`

- 徒歩通行可能な道路を**タイル単位**で取得する
- 取得済みタイルは端末内に保存し、2 回目以降はオフラインで動作する
- 未取得のタイルにかかる場合、そのタイルを取得して既存のグラフに繋ぐ
- 取得済みタイルの一覧を確認し、個別に再取得・削除できる
- **モバイル通信中は自動取得を行わない**

実運用では [F-10](#f-10-オフラインデータの一括投入-p1) で関東全域を事前投入するため、
F-8 は開発中および小規模なエリア追加のための手段と位置づける。

→ [タイル方式の設計](./design.md#2-道路網データ)

### F-1: 地図表示と現在地 `P0`

- 地図を全画面表示し、ピンチズーム・パンができる
- 位置情報の許可を求め、現在地にマーカーを表示する
- 初期表示は現在地を中心にする
- 許可が拒否された場合の表示を用意する

### F-4: 散歩ルートの提案 `P0`

- 目的地を指定できる
- 現在地から目的地までのルートを探索する
- **幹線道路を避けつつ、最短性も損なわないこと**
- 提案ルートを地図に線で表示する
- ルートの総距離と推定所要時間を表示する
- 経路が見つからない場合の表示を用意する

**ルート形状:** 目的地あり（A→B）。周回コースは対象外。

→ [コストモデルと探索方式](./design.md#1-ルート提案エンジン)

### F-9: ルートの多様性 `P0`

**「毎回同じルートを出さない」ための要件。**

- 提案したルートの通過区間を端末内に記録する
- 過去に提案した区間は選ばれにくくする
- その効果は時間経過とともに減衰させる
- 同じ目的地を再指定した際、**全区間ではなく一部区間が変わる**ことを許容する
- 多様性のために不自然な遠回りを提案しないこと

**実装順:** まず「提案した」履歴のみで動かす。[F-2](#f-2-散歩の記録-p1) 完成後、「実際に歩いた」記録も加える。

→ [履歴係数](./design.md#13-コストモデル)

### F-10: オフラインデータの一括投入 `P1`

**目的: 散歩中にモバイル通信を一切発生させない。**

- 関東地方 7 県分の道路網を、自宅 Wi-Fi 環境でまとめて端末に投入する
- 投入後は [F-4](#f-4-散歩ルートの提案-p0) の経路探索が**通信なしで完結する**
- 端末上での事前処理に長時間かからないこと
- 同じ手順でデータを更新できる。**更新しても [F-9](#f-9-ルートの多様性-p0) の提案履歴が失われないこと**

**更新頻度:** 定期更新は必須ではなく、年 1 回程度で足りる（[根拠](./design.md#34-更新の頻度)）。

→ [取得元と前処理](./design.md#3-オフラインデータの一括投入)

### F-7: ルートの追従 `P1`

- 散歩中、提案ルートの線と現在地マーカーが地図上に同時に表示され続ける
- 地図が現在地に追従する（追従の ON/OFF ができる）

**必要なレベル:** 地図表示のみ。曲がり角での通知・音声案内は行わない。

### F-2: 散歩の記録 `P1`

- 歩いた軌跡を地図に線で描画する

**制約:** フォアグラウンド記録のみ。画面を消すと止まる（→ [F-6](#f-6-バックグラウンド記録-p3)）。

### F-3: 散歩履歴の閲覧 `P2`

- 記録した散歩を一覧表示する（日時・距離・所要時間）
- 選択するとルートを地図に表示する
- 削除できる

### F-6: バックグラウンド記録 `P3`

- 画面を消していても記録が継続する

**前提条件:** 開発ビルドが必須。[環境制約](#環境制約)により現状は着手できない。

## 5. 非機能要件

| 項目 | 決定 |
|---|---|
| 対象プラットフォーム | iOS（iPhone 実機） |
| データ保存先 | 端末内のみ。サーバー・クラウド同期はしない |
| オフライン動作 | **散歩中は完全オフラインで動作すること** |
| 外部通信 | 自宅 Wi-Fi 環境での道路網データ投入時のみ |
| 位置情報の扱い | 端末外に送信しない |
| 配布方法 | 開発中は Expo Go。App Store 配信はしない |

### 環境制約

**開発マシンではネイティブビルドができない。**

| 項目 | 現状 | Expo SDK 54 の要求 |
|---|---|---|
| macOS | 12.7.6 (Monterey) | Xcode 16.1 のために 14 以上が必要 |
| Xcode | 未インストール（Command Line Tools のみ） | 16.1 以上 |

**影響:**

- ローカルビルドは不可。開発ビルドを要する [F-6](#f-6-バックグラウンド記録-p3) は着手不可
- それ以外の全機能は Expo Go で開発・動作確認できる

**解消するには（将来必要になったら）:**

1. macOS を 14 以上にアップグレードし Xcode 16.1 以上を入れる
2. EAS Build を使う。ただし実機用の開発ビルドには Apple Developer Program（年 $99）が必要

→ [使えるツール・使えないツール](./design.md#5-開発環境)

## 6. 将来の検討事項

- **周回コース**（出発地に戻るコース）の生成。「30 分歩いて帰ってくる」型。
  A→B とはアルゴリズムが別物になるため、F-4 完成後に改めて検討する
- **夜道の明るさ**を考慮する（OSM の `lit` タグ。付与率は未調査）
- **坂道**の回避／選好（標高データが別途必要）
