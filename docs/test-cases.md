# walk-app テストケース

最終更新: 2026-08-08

要件は [requirements.md](./requirements.md)、設計は [design.md](./design.md)、作業手順は [development-plan.md](./development-plan.md) を参照。

## 方針

**テスト駆動で進める。** 実装より先にテストを書き、落ちることを確かめてから実装する。

| 項目 | 内容 |
|---|---|
| 実行 | `npm test`（監視は `npm run test:watch`） |
| 構成 | `jest-expo` プリセット |
| 置き場所 | `__tests__/<モジュール名>-test.ts` |

この表の「ケース」は、テストコード中の `it(...)` の文言とそのまま対応させる。
片方だけ変えないこと。

## 何をテストで押さえ、何を実機で見るか

`lib/` は純粋なロジックなので、実機なしで確かめられる。
実機が要るのは、地図の描画・GPS・実際に歩いた結果だけ。

| 対象 | 確認方法 |
|---|---|
| タイル計算、コストモデル、グラフ構築、経路探索 | **自動テスト** |
| Overpass からの取得（通信あり） | 実機。取得数を[実測値](#実測値との突き合わせ)と突き合わせる |
| 地図表示、現在地、ルート描画 | 実機（室内） |
| 幹線回避が体感に合うか、多様性、バッテリー | 実機（外を歩く）。[動作確認の場所](./development-plan.md#動作確認の場所) |

## lib/tiles.ts — タイル計算

`__tests__/tiles-test.ts`

### tileAt

| ケース | 目的 |
|---|---|
| 開発エリアが実測したタイルと一致する | 実測に使った bbox とズレていないことの固定 |
| タイル境界ちょうどの座標が、そのタイルの内側に入る | **回帰テスト。** 度のまま割ると `139.70 / 0.02 = 6984.999999999999` となり、境界の座標が隣のタイルに落ちる |
| 任意の座標が、自分のタイルの範囲内に収まる | 2 万点の走査。境界の取りこぼしが無いこと |
| 小数 7 桁より細かい差は無視して上のタイルに入れる | OSM の座標精度に丸める仕様の明示 |
| 負の座標でも下側に丸める | 赤道・本初子午線をまたぐ側の挙動 |

### tileBounds

| ケース | 目的 |
|---|---|
| 誤差のない値を返す | Overpass の bbox 文字列が汚れないこと |
| 1 辺が TILE_SIZE になる | [タイルの定義](./design.md#21-タイルの定義)どおりの大きさ |
| 隣接タイルが隙間なく接する | 取りこぼし・重複が出ないこと |

### tileKey / tilesAround

| ケース | 目的 |
|---|---|
| 往復して元に戻る | DB のキーに使うため |
| 中心を含む 9 枚を返す | [F-8](./requirements.md#f-8-道路網データの取得) の 3×3 確保 |
| 中心から上下左右 1 枚ずつの範囲に収まる | 同上 |

## lib/cost.ts — コストモデル

`__tests__/cost-test.ts`

| ケース | 目的 |
|---|---|
| 設計表の値を返す | [種別係数](./design.md#13-コストモデル)と実装のズレを防ぐ |
| 歩行者専用道が生活道路より安く、幹線が高い | **大小関係そのものが要件。** 値を調整しても壊れてはいけない順序 |
| 接続路は接続元と同じ係数になる | 実データにある `primary_link` などの扱い |
| 表に無い種別は 1.0 になる | `cycleway`・`rest_area`・`corridor` など、設計表で網羅できていない種別 |
| 接続元も未知なら 1.0 に落ちる | フォールバックの二段目 |
| タグが無ければ補正しない | `lanes` は日本の生活道路にほぼ無い（[前提調査](./design.md#11-前提調査-lanes-タグは使えない)） |
| 2 車線以上は 1.5 倍 / 1 車線以下は 0.9 倍 | 補正の値 |
| 解釈できない値では補正しない | `lanes=unknown` のような実データ |
| 複数値や小数でも先頭の数値で判断する | `lanes=2;3` のような実データ |
| 種別係数と車線補正を掛け合わせる | `primary` かつ 2 車線 → 12.0 |
| 車線タグが無ければ種別係数そのまま | 補正が勝手に掛からないこと |
| highway が無くても落ちない | タグ欠損への耐性 |

**値そのものは[未決事項](./requirements.md#7-未決事項)。** 実際に歩いて調整するため、
テストは「設計表と一致すること」と「大小関係」を押さえ、値の妥当性は問わない。

## lib/overpass.ts — 道路網の取得

`__tests__/overpass-test.ts`

通信そのものはテストしない。`fetchImpl` を差し替えて、
**クエリの組み立て・応答の解釈・エンドポイントの切り替え**を確かめる。

| ケース | 目的 |
|---|---|
| フォールバック先を複数持つ | 公開サーバーは過負荷で 504 を返す。実測で overpass-api.de 17 秒に対し kumi.systems 3 秒 |
| way と node に分けて返す | 応答の解釈 |
| タグの無い way でも落ちない | データ欠損への耐性 |
| タイルの bbox をクエリに含める | [タイルの定義](./design.md#21-タイルの定義)どおりの範囲を要求すること |
| ノード ID が返る取得形式を使う | **`out geom` に戻すと隣接タイルを ID で繋げなくなる**（[タイル間の接続](./design.md#23-タイル間の接続)） |
| 1 つ目が成功すれば 2 つ目は叩かない | 公共サービスに余計な負荷をかけないこと |
| 504 が返ったら次のエンドポイントを試す | 過負荷時の回復 |
| 通信そのものが失敗しても次を試す | 圏外・切断からの回復 |
| 全滅したら、試した結果が分かるエラーを投げる | どのエンドポイントがどう失敗したか分かること |
| 種別ごとに数え、多い順に並べる | 取得結果の目視確認用 |
| highway が無い way も数える | 取りこぼさないこと |

## lib/graph.ts — グラフ構築

`__tests__/graph-test.ts`

### distanceMeters

| ケース | 目的 |
|---|---|
| 同じ点は 0 | |
| 既知の距離とおおよそ合う | 東京駅–横浜駅 約 27km |
| 緯度 0.001 度はおよそ 111m | 桁を間違えていないこと |
| 向きを変えても同じ距離 | 対称性 |

### buildGraph

| ケース | 目的 |
|---|---|
| 交わらない 1 本の way は 1 エッジになる | 過剰な分割をしないこと |
| 途中の形状点をエッジの geometry に残す | 地図に描くとき道の形が保たれること |
| 他の way と共有するノードで分割する | **ここが肝。** 間違えると経路が繋がらない |
| way の両端は共有されていなくてもノードになる | 行き止まりと、隣接タイルとの接続点 |
| 種別ごとの係数をエッジに持たせる | 探索が係数を使えること |
| 孤立したノードを作らない | 到達不能な断片が生じないこと |
| 環状の way でも同じ点に戻る区間を作らない | 長さ 0 のループを作らない |
| 座標が欠けた way は無視する | データ欠損への耐性 |
| ノードが 1 つしかない way は無視する | 同上 |
| 空の入力でも落ちない | 同上 |

### neighbors

| ケース | 目的 |
|---|---|
| 両方向に辿れる | 徒歩なのでエッジは無向 |
| 交差点から全ての方向を列挙する | 探索が分岐を見落とさないこと |
| 知らないノードでは空を返す | 例外を投げないこと |

## lib/db.ts — タイルの保存

`__tests__/db-test.ts`

**実際の SQLite に対してテストする。** `node:sqlite`（Node 22 に同梱）を
`expo-sqlite` と同じ形の口で包み、SQL そのものを確かめる。
実機では `lib/store.ts` が `expo-sqlite` を渡す。

保存するのは Overpass が返した生の way / node で、グラフではない。
**グラフは読み込んだタイル全体から組み立てる**必要があるため
（あるノードが交差点かどうかは隣のタイルを読んだ時点で変わる）、
タイルごとにエッジを作って保存すると辻褄が合わなくなる。

| ケース | 目的 |
|---|---|
| 何度呼んでも落ちない | 起動のたびに `initSchema` を通すため |
| 保存したタイルを取得済みと判定する | 通信するかどうかの判断 |
| 取得済みタイルを一覧できる | [F-8](./requirements.md#f-8-道路網データの取得) の確認手段 |
| 同じタイルを二度保存しても重複しない | 再取得しても増えないこと |
| 保存した way と node をそのまま返す | タグと node 参照が往復すること |
| 未取得のタイルを指定しても落ちない | 初回起動 |
| タイルを指定しなければ空を返す | 空配列で SQL を組まないこと |
| 複数タイルをまとめて読める | 3×3 の読み込み |
| 境界をまたぐ way は、どちらのタイルからも読める | Overpass は bbox 外まで返す（[タイル間の接続](./design.md#23-タイル間の接続)） |
| 両方のタイルに含まれる way を二重に返さない | OSM ID で重複排除できていること |
| way が参照する node は、別タイル由来でも揃う | **境界の way が欠けたノードを指さないこと。** 欠けるとその way が捨てられ、タイルが繋がらない |

## lib/probe.ts — 大きな DB の検証（Step 1-4）

`__tests__/probe-test.ts`

[F-10](./requirements.md#f-10-オフラインデータの一括投入) が置く約 900MB を
Expo Go が扱えるか確かめるための使い捨ての DB。
中身に意味は無いので `randomblob` で 1MB ずつ膨らませる。

| ケース | 目的 |
|---|---|
| 空の DB でもサイズを返す | `PRAGMA page_count` × `page_size` で測れること |
| 行を足すと増える | サイズ計算が実態を追うこと |
| 目標サイズまで膨らませる | 900MB に届くこと |
| すでに目標に達していれば何も足さない | 押すたびに膨らみ続けないこと |
| 進捗を報告する | 実機で数分かかるため、進み具合が見えること |
| 中断できる | **途中でやめられること。** 端末の容量を守る |
| 行数と、読み出したデータのサイズを返す | 書けるだけでなく読めること |
| 空でも落ちない | 未生成の状態 |

**実機で確かめること:** 900MB に到達するか、クエリが返るか、削除できるか。
テストでは小さい目標値（数 MB）で論理だけを押さえている。

### lib/probe-store.ts — 開閉と削除の順序

`__tests__/probe-store-test.ts`

**expo-sqlite の削除は当てにしない。** 開いたままの接続があると失敗し、
例外を投げずに成功したように見えてもファイルが残ることがある。
接続を閉じて削除を試みたあと、**ディスクを見て残っていたら直接消す**。
フェイク側でこれらの挙動を再現して確かめる。

| ケース | 目的 |
|---|---|
| 二度開いても接続を使い回す | 接続が増え続けないこと |
| 削除する前に接続を閉じる | **回帰テスト。** 閉じずに削除して「Calling the deleteDatabaseAsync function has failed」になっていた |
| 開いていなくても削除できる | 一度も開かずに押した場合 |
| expo-sqlite が消せなかったら、ファイルを直接消す | **回帰テスト。** 例外は出ないのに 900MB が残り続けた |
| deleteDatabaseAsync が例外を投げても、ファイルを直接消して回復する | 例外で止まらないこと |
| WAL の付随ファイルも一緒に消す | `-wal` / `-shm` の取り残しを防ぐ。他の DB は消さない |
| それでも消えなければ、残っているものを報告する | 黙って失敗しないこと |
| 削除したあとに開くと、新しい接続になる | 消えた DB の接続を掴み続けないこと |
| 閉じたあとに閉じても落ちない | 二重呼び出し |
| 開いていない状態で閉じても落ちない | 同上 |
| 削除に失敗したら、接続を持ち越さない | 失敗後もずっと失敗し続けないこと |

## 実測値との突き合わせ

自動テストでは通信しない。取得が正しいかは、開発画面に出る値を
下表と突き合わせて判断する（開発タイル: 武蔵小山 `6985/1781`）。

| 項目 | 実測値 |
|---|---|
| way | 1,806 |
| node | 6,391 |
| 交差点ノード | 2,767 |
| エッジ | 3,777 |
| 総延長 | 162.9 km |
| 孤立ノード | 0 |

数値がずれた場合の切り分け:

- **way / node がずれる** → タイル計算か、Overpass の抽出条件
- **way / node は合うがグラフがずれる** → 分割処理（`buildGraph`）
- **孤立ノードが 0 でない** → 隣接リストの構築漏れ
